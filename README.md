# 赛事消费异常联防

本项目用于整理赛事消费异常联防领域中的事件名称、交换字段与脱敏样例，并在其之上提供
跨城赛事投诉的**联合处置案件模型**：把交易凭证、商户承诺、权益核销、责任分摊、处理时钟
和消费者选择关联成一笔可追溯案件，方便业务、运营和研发人员在同一套术语下讨论后续服务。
资料只包含领域约定与虚构数据，不包含真实个人信息、生产连接或外部账号。

## 目录

- `src/event_consumer_guard.py`：事件种类与最小字段校验。
- `src/joint_case.py`：联合处置案件聚合（事件溯源、责任项、时钟、改判、结算、可见性）。
- `data/sample.json`：用于核对资料格式的虚构事件。
- `tests/`：保证样例、领域约定与案件不变量保持一致。

## 联合处置模型

案件（`JointCase`）采用**事件溯源**：命令只做校验并向事件流追加不可变事件，状态由事件
重放得到（`JointCase.rebuild`）。存储可选用 `InMemoryEventStore` 或 append-only 的
`FileEventStore`（JSONL，每行一个事件，追加即 flush——服务重启后重放日志即可恢复全部
待办，重复扫描升级也是幂等的）。

案件时间线把以下要素关联在一起：

| 要素 | 说明 |
| --- | --- |
| 证据 `submit_evidence` / `record_redemption` | 交易凭证、权益核销等；按 `evidence_id` 幂等，迟到或重复提交返回原事件，不产生第二条记录 |
| 个人材料撤回 `withdraw_evidence` | 留下撤回墓碑，其他参与方看不到内容哈希，提交者本人与监管仍可核对 |
| 承诺 `record_commitment` | 记录承诺由哪一方作出，作为责任认定依据 |
| 责任项 `add_item` / `claim_item` | 案件可拆分为多个责任项；仅被指派方可认领，并发下只成功一次；非必需责任项可取消 |
| 处理时钟 `sweep` | 截止时间接受任意时区（内部统一 UTC）；超时产生 L1，超过 24h 宽限产生 L2，每级只触发一次 |
| 决定与消费者选择 `propose_decision` / `accept_decision` | 部分退款、替代权益等须附依据证据，消费者接受后才成为生效补救 |
| 人工改判 `propose_override` / `withdraw_override` | 原决定、依据、改判人与理由永久保留；消费者须重新接受；撤回改判则原决定继续生效 |
| 结案 `close_case` | 所有必需责任项完成才能结案；非必需项处于处理中也会阻止结案 |
| 结算批次 `create_settlement_batch` / `confirm_batch` | 只纳入已完成、已履行、金额为正且未进过批次的责任项 |
| 按方视图 `view_for` | 未授权参与方只能看到自己负责的责任项、自己提交/被引为依据的证据与本方承诺 |

强制不变量：

1. **局部升级**：某一方超时只升级对应责任项，不自动退款、不影响其他责任项。
2. **补救不失效、不重复**：改判待确认期间旧决定仍生效但不得履行；履行后禁止改判、
   禁止二次履行，已接受的补救不会因改判而失效。
3. **金额守恒**：`settlement_audit()` 校验
   `已履行金额 == 已入批次金额 + 待入批次金额`，且同一责任项在批次中至多一条、
   条目金额必须等于生效决定金额（改判后按最终金额结算一次）。
4. **幂等**：所有命令支持 `command_id`，网络重试在业务校验之前即被拒绝；重启重放后
   幂等键仍然生效。
5. **可解释**：`explain()` 输出每个责任项的当前责任方、状态、下一步、金额与守恒结果，
   客服可直接据此答复消费者。

## 本地核对

```bash
python3 -m unittest discover -s tests
python3 -m compileall -q src tests
```

测试（`tests/test_joint_case.py`，26 个用例）覆盖：并发认领（16 线程）、迟到/重复证据与核销、
命令重试幂等、跨时区截止与局部升级、改判留痕与撤回、履行锁定、结案门禁、结算不重不漏与
金额守恒、按方可见性、个人材料撤回、以及基于 JSONL 重放的故障恢复。
