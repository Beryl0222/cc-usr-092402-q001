# 赛事消费异常联防

本项目用于整理赛事消费异常联防领域中的事件名称、交换字段与脱敏样例，方便业务、运营和研发人员在同一套术语下讨论后续服务。资料只包含领域约定，不包含真实个人信息、生产连接或外部账号。

## 目录

- `src/event_consumer_guard.py`：对外事件种类、最小字段校验，以及联合处置内部事件信封（`JOINT_EVENT_TYPES`、`validate_joint_envelope`）。
- `src/jointcase/`：在赛事消费事件合同之上构建的**联合处置案件**能力。
  - `domain.py`：案件聚合根（事件溯源）。案件拆分为多个责任项，证据/判罚/补救动作/消费者选择全部是追加事件。
  - `clock.py`：跨时区处理时钟，截止时间一律以带时区的绝对时间点比较，拒绝朴素时间戳。
  - `store.py`：每案件一个 JSONL 追加日志，`fcntl` 文件锁 + 期望序号 CAS，只追加不改写。
  - `service.py`：命令执行、参与方授权、并发认领的 CAS 重试、超时局部升级、重启待办恢复。
  - `projections.py`：客服案件时间线、当前责任/下一步/金额守恒汇总、参与方最小可见视图。
  - `settlement.py`：财务跨案件结算批次，按已确认结果生成，不重不漏。
- `data/sample.json`：用于核对资料格式的虚构事件。
- `tests/`：领域约定与联合处置规则的自动化测试。

## 联合处置案件如何对应业务诉求

| 业务诉求 | 落地方式 |
| --- | --- |
| 一笔投诉关联成可追溯案件 | `CaseOpened` 关联投诉号与交易凭证，后续所有记录挂在同一案件事件流上 |
| 相同证据迟到或重复 | 证据按 `source_party + evidence_id` 幂等去重；任何阶段都可到达；结案后的**关键证据**触发 `CaseReopened`，非关键证据只收录不翻案 |
| 未经授权的参与方只能看到自己负责的部分 | 服务层做命令授权，`projections.party_view` 做读过滤：商户/平台只看到自己认领的责任项、自己的证据与动作、判罚中自己的那一档金额 |
| 人工改判保留原决定与依据 | 改判是新的 `DecisionRecorded`，必须用 `supersedes_event_seq` 标注被替代版本；旧版本事件永不删除，时间线标注"初判/改判" |
| 案件可拆分，结案必须等待所有必需动作 | 一个案件多个责任项；结案校验全部责任项已判罚、全部动作已完成、消费者已选择 |
| 某一方超时只升级对应责任项 | `ItemEscalated` 只作用于该责任项与该动作，可携带新监管截止时间重置时钟；其他责任项与已完成补救不受影响 |
| 不能重复退款、已接受补救不失效 | 资金动作金额受判罚总额约束（守恒）；已完成的 `REFUND` 后禁止再派 `REFUND`，差额只能 `TOPUP_REFUND`；改判总额不得低于消费者已到手金额 |
| 跨时区截止时间 | 内部统一为带时区绝对时间点，录入时从参与方本地时区换算，夏令时不改变物理时长 |
| 撤回中的个人材料 | `PersonalDataRedacted` 清空证据正文，保留来源/类型/时间/哈希及其支撑的判罚，重复撤回幂等 |
| 服务重启后待办恢复 | 无独立待办库：重放 JSONL 日志即恢复；`scan_pending`/`recover_and_escalate` 扫描超时责任项 |
| 客服解释当前责任、下一步、金额守恒 | `timeline` 与 `case_summary` 给出时间线、责任方、下一步和 `decided ≥ assigned ≥ settled ≥ batched` 守恒视图 |
| 财务不重不漏结算 | 已完成资金动作只能进入一个批次（事件层永久标记）；改判补发完成后进入后续批次；批次生成后可复核确认 |

## 本地核对

```bash
python3 -m unittest discover -s tests
python3 -m compileall -q src tests
```

测试覆盖：并发认领（线程与多进程）、迟到/重复证据与结案后重审、局部超时升级（含时钟重置与不重复升级）、人工改判留痕与金额守恒、跨时区时钟、个人材料撤回、参与方可见性、结算批次不重不漏，以及服务重启后的待办恢复。
